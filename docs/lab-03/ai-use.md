## My Reflection

### Specification-Agent Reflection
Using the AI as a specification agent before writing implementation code was invaluable for Lab 3. The scope expanded significantly from a single-role MVP in Lab 2 to a complex multi-role service desk (`REQUESTER`, `IT_STAFF`, `ADMINISTRATOR`) with distinct data boundaries, state progression constraints, and administrative safety guards. The AI helped systematically decompose the assignment into Functional Requirements (`FR-01`–`FR-27`), Business Rules (`BR-01`–`BR-23`), and Acceptance Criteria (`AC-01`–`AC-25`). Creating this contract upfront ensured 100% test traceability and prevented breaking legacy Lab 2 functionality through the dual-domain seed strategy.

### Coding-Agent Reflection
As a coding assistant, the AI provided massive acceleration across full-stack feature delivery. It wrote repetitive boilerplate code—such as Express route handlers, bcrypt password validation, Prisma query filters, and Bootstrap responsive layouts—with high precision. However, working with a coding agent required active technical oversight:
- **Asynchronous Timing & Test Flakiness:** The AI initially used naive `waitForTimeout` calls in Playwright, which caused flaky tests when network latency fluctuated. I guided the agent to replace these with deterministic network response listeners (`waitForResponse`) and specific DOM element assertions.
- **Security & Business Logic Edge Cases:** When handling unauthorized resource access, the agent had to be carefully steered between returning `403 Forbidden` (role mismatch) versus `404 Not Found` (anti-enumeration under BR-20). Constant review of API contracts and running automated test suites was essential to ensure compliance with security requirements.
